# تشغيل بيانات AcademyHub التجريبية

## المطلوب قبل التشغيل

- تطبيق Migrations الخاصة بـTrainingDbContext.
- اختيار قاعدة AcademyHubTrainingDb في SQL Server Management Studio.
- استخدام بيئة تطوير وبيانات وهمية فقط، وأخذ نسخة احتياطية لو القاعدة تحتوي بيانات مهمة.

## التثبيت والتشغيل

١. ضع الملف seed-demo.sql داخل مجلد scripts في جذر المشروع.
٢. افتحه في SSMS واختر قاعدة التدريب.
٣. شغّل الملف كاملًا مرة واحدة. السكربت يتوقف إذا اخترت قاعدة مختلفة؛ عدّل ExpectedDatabase فقط لو غيّرت اسم قاعدة التدريب عمدًا.
٤. افتح Course/Index واستخدم View course لرؤية الطلاب والدرجات.
٥. سجّل حسابًا من واجهة التطبيق وأنشئ كورسًا خاصًا بك لتجربة التعديل والحذف.
٦. أعد تشغيل السكربت للاختبار: يستخدم السجلات التجريبية الموجودة ولا يعيد إضافتها في التشغيل المتتابع المعتاد.

## ماذا يضيف؟

- محاضرين تجريبيين مع Profile لكل منهما.
- خمسة طلاب تجريبيين.
- ثلاثة كورسات، اثنان بهما تسجيلات وواحد بدون تسجيلات.
- خمس تسجيلات، بدرجات متنوعة ودرجة null لاختبار Pending.

الأسماء تبدأ بـDemo لتمييزها عن بياناتك الحالية. تكرار أسماء العرض غير ممنوع في نموذج المشروع، لذلك السكربت يتوقف إذا وجد أسماء تجريبية ملتبسة بدل اختيار طالب عشوائيًا.

## ملكية الكورسات

القيمة الافتراضية CreatedByUserId هي demo-seed: علامة للبيانات التجريبية وليست مستخدمًا حقيقيًا. لذلك الكورسات تظهر للعرض العام، لكن حسابك لن يستطيع تعديلها أو حذفها.

لا تنشئ حسابًا باسم demo-seed، ولا تضع كلمة مرور في SQL. الأفضل تجربة CRUD بكورس تنشئه من الفورم. لو أردت اختبار منع الحذف على كورس تجريبي فيه تسجيلات، يمكنك تعيين DemoOwnerUserId لمعرّف حساب تجريبي حقيقي قبل أول تشغيل على قاعدة جديدة. هذا تخصيص محلي؛ لا تضع معرّف حسابك في النسخة المنشورة. السكربت لا يغيّر ملكية كورسات سبق إدراجها.

## ما الذي لا يفعله؟

- لا يضيف مستخدمين أو كلمات مرور إلى Identity.
- لا يحذف أو يعدّل بياناتك الحالية.
- لا ينشئ قواعد بيانات أو جداول.
- لا يفترض أرقام Id ثابتة للكورسات أو الطلاب؛ يعرض الأرقام الفعلية بعد الإدراج.
- لا يضمن سلامة تشغيل نسختين منه في نفس اللحظة؛ شغّله متتابعًا على قاعدة تطوير.
- لا يضيف CHECK constraint للدرجة؛ Range على Entity وحدها لا تنشئ قيد SQL تلقائيًا. البيانات التي يضيفها هنا داخل النطاق.

## التحقق المقترح على جهازك

- شغّل على قاعدة تطوير بعد Migrations؛ تأكد أن النتائج تعرض 3 كورسات تجريبية.
- شغّله ثانية؛ تأكد من عدم زيادة عدد السجلات التجريبية بسبب الإعادة.
- افتح تفاصيل كورس ASP.NET Core MVC: 3 تسجيلات، بينها Pending.
- افتح SQL Server Fundamentals: حالة قائمة الطلاب الفارغة.
- جرّب إنشاء وتعديل وحذف كورس حسابك من الواجهة بشكل منفصل.

تمت مراجعة السكربت مقابل الكيانات وTrainingDbContext المرسلة، لكنه لم يُنفذ ضد SQL Server داخل بيئة المساعد. إذا اختلفت Migrations الفعلية عن الكود، راجع Schema قبل التشغيل.
